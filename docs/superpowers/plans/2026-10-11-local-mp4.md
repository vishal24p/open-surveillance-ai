# Local MP4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run local MP4 footage repeatedly through the existing detection, tracking, incident, and evidence pipeline.

**Architecture:** A VideoFileSource in the existing camera package exposes read/close and video position in seconds. LivePipeline accepts an optional frame clock; main selects the source with argparse. Camera timing remains unchanged.

**Tech Stack:** Python 3.11, argparse, pathlib, installed OpenCV and unittest; no new dependencies.

**Spec:** User's MP4 request and confirmed answers in this chat; MILESTONES.md Milestone 1 evaluation extension.

## Global Constraints

- `uv run python main.py --video "clip.mp4"` selects MP4; no flag keeps DroidCam.
- Use video timestamps, process every frame as fast as possible, and preserve the existing renderer.
- EOF closes resources and marks unfinished evidence incomplete; never invent post-roll frames.
- Reuse the same tracker, incident rules, and evidence recorder.
- MP4 must not require a camera index; person confidence retains existing validation.
- Keep unrelated changes untouched; do not commit or push this feature yet.
- MP4 calendar timestamps use run-start time plus video position; dates differ between runs, durations use video time.

## Review Focus

- Missing/unreadable local file: useful error, release any capture handle.
- Missing/non-increasing video timestamps: reject rather than use processing time.
- Slow/fast processing: identical dwell and clip duration.
- EOF or Q during active recording: incomplete metadata and released resources.
- Default DroidCam behavior and existing tests: remain working.
